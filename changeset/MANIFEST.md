## The original brief, and what it turned into

The ask was: add the technologies from the D&B spreadsheet, revamp the project,
add tests, and make sure the catalog is "100% coherent with what gets extracted".
Auditing the last of those first turned out to matter most, because the catalog
was not coherent and the update script would have made it worse.

### 1. The engine crashed on bad catalog data

`resolve()` threw on a dangling `implies`/`excludes` reference, aborting an
entire scan. Confirmed live: detecting `Juniper` or `Amazon Augmented AI` threw.
Defects are now collected on `Wappalyzer.errors` and surfaced by the validator,
so one bad entry cannot take down a run.

Also fixed in `wappalyzer.js`:

- `setTechnologies()` was not idempotent — calling it twice corrupted
  `requires`/`categoryRequires`. It now resets derived state.
- An unknown category id crashed the priority sort. Categories are now resolved
  once per detection, so an unknown id is reported once and dropped.
- `analyzeManyToMany()` had no guard for a non-object channel or a missing
  regex; both now return no match instead of throwing.
- `saas` and `oss` were curated in the data and silently dropped by the engine.
  They are now surfaced through `resolve()` and the CLI output.
- `analyzeJs`/`analyzeDom` moved out of `driver.js` so they are testable without
  puppeteer.

### 2. The update script destroyed local work

`merge-update.js` replaced any technology that also existed upstream. That
silently discarded locally-authored fingerprints — `Salesforce Service Cloud` and
`Microsoft Application Insights` each carry local cookie/dom/meta/xhr patterns
and far more specific `scriptSrc` lists than upstream ships.

**This was fixed before the update was run**, so nothing was lost. The merge is
now additive at field level (`scripts/lib/merge.js`): channels, categories,
pricing and references are unioned; scalar metadata prefers the local value.
`test/merge.test.js` guards the specific regression.

`preferLocalShape()` also keeps the local representation when a merge adds
nothing. Without it, the first clean run rewrote 5,083 entries purely to collapse
`["a"]` into `"a"` — semantically identical, and enough noise to make the diff
unreviewable. Every future upstream pull benefits.

### 3. ~180 patterns could never fire

Found by the new validator, fixed by the new normalizer:

| Defect | Count | Effect |
| --- | --- | --- |
| `script` instead of `scriptSrc` | 52 | Field not read; pattern dead |
| Keyed channel written as string/array | 16 | `analyzeManyToMany` keys on indices |
| Flat channel written as an object | 12 | `analyzeOneToOne` bails |
| Invalid `dom` rules (`content`, `version`, `exists: true`) | 29 | Collector never reports them |
| Malformed `probe` schemas | 10 | Driver would request `/0`, `/1`, … |
| Nested `js` objects | 4 | Collector does not walk into them |
| `dns` keys the driver never resolves | 3 | Channel never receives values |
| Duplicate names across letter files | 85 | Last load silently won |
| Misfiled into the wrong letter file | 590 | Churn on every merge |
| Invalid/missing category ids | 4 | Undefined category |

### 4. Coverage against the request list

47% → **96% catalog-matchable**, 100% mapped. `Catalog-matchable` means a
detection path exists and passes synthetic tests; it is not empirical live-scan
coverage. Two reframings did most of it:

- **"Back-end" tools ship web UIs.** Airflow, Superset, MLflow, Argo CD,
  Metabase, Prometheus, Prefect, Spark, Flink, Kiali, Ray, Kubeflow, Rancher,
  Kedro-Viz, AutoGPT and the Kubernetes/OpenShift consoles are routinely exposed
  on a subdomain. Patterns were read from each project's shipped index template.
- **A model's output is evidence of the model.** An image from
  `cdn.midjourney.com` was made with Midjourney. Generated-media CDNs plus
  hosted provider APIs cover the image, video, music and language models.

### 5. The evidence behind the numbers is now reproducible and measured

Two claims were unverifiable when the audit was raised. Both are resolved.

**The DNS sweep is reproducible.** The original run retained no corpus, so its
markers were labelled `unreproduced-prior-sweep`. The corpus is now committed
(`data/dns-sweep-domains.txt`, 536 domains) and `scripts/dns-sweep.js` reads the
tokens **from the catalog**, so it measures exactly what ships and doubles as a
regression check. Latest run: 513/536 domains returned TXT records (23 returned
none, 0 failed to resolve), **94 of 96 catalog markers observed**. The two
unobserved markers are upstream's.

The retained results now carry provenance — timestamp, corpus SHA-256, marker-set
SHA-256, resolver servers, Node version — and classify every domain by resolution
outcome, so a timeout is no longer indistinguishable from "publishes no TXT".
`npm run sweep:check` re-hashes both inputs and **exits non-zero if the retained
results are stale**.

Stated precisely, because an earlier version of this claim was wrong: **all 55
enriched technologies have at least one observed retained marker; five original
pattern strings were superseded** during redundancy removal (Detectify, Dropbox,
Segment, Mixpanel, DocuSign) and are labelled
`corpus-observed-via-equivalent`. 48 are observed by their exact string. The
labels are derived from the retained results at load time rather than hard-coded,
which is what previously left the report asserting `unreproduced-prior-sweep`
after the sweep had become reproducible.

Deriving tokens from the catalog also exposed **redundant patterns**: upstream's
`mixpanel-domain-verify` and a local `mixpanel-domain-verify=` matched the
identical 52 domains. `dropSubsumedPatterns()` removed 18 such patterns
catalog-wide. Three guards were needed — a `\;version:` pattern is never
redundant (the first
version would have destroyed jQuery, WooCommerce and Genesys version detection);
dropping in favour of a `\;confidence:` pattern silently lowers confidence; and
**`dom` and `probe` must be excluded entirely, with only literal patterns taking
part at all**. That third guard came from review after the rule had already
deleted three real detections — `script#apple-pay-shop-capabilities`,
`div.asciinema-player-wrapper` and `div[data-swiper-slide-index]` — because
substring containment says nothing about CSS selector matching. All three are
restored and `test/catalog.test.js` asserts no `dom`/`probe` pattern is ever
dropped.

**The xhr channel was measured, and the result is uncomfortable.** 126 of the 387
catalog-matchable products rest on `xhr` alone. **1 of 85 xhr-only markers
appeared in a 29-page corpus under the current request-aborting driver**, while 47
xhr hostnames were collected — all marketing and telemetry infrastructure, no
vendor API hosts, not even on those vendors' own sites.

That figure is a **yield, not an observation rate**, and the report says so.
Nothing maps each marker to a page where its vendor is in use; `driver.js` aborts
every non-document/script request, which suppresses the follow-on calls that would
have exercised other markers; and only 8 of the 29 pages returned a clean 200 (12
were 304, one 403, four recorded no status). The retained results record the
status distribution and blocked pages so "29/29 scanned" cannot hide it.

The entries were kept — they are correct, and a client-side integration does fire
them — but `npm run coverage` now reports the count, frames 96% as an upper bound
and the yield as a lower bound, with tests asserting the caveat cannot be dropped
from either output.

Concrete retained examples are listed in `docs/live-evidence.md`.

## What was deliberately not done

These were each an easy increase to the coverage number and were rejected:

- **`google-site-verification`** appeared on 445 of 518 domains, the single
  fattest token in the sweep. Search Console sets it too, so it says nothing
  about Google Workspace. The Workspace-specific recovery record is used instead.
- **Mapping Seldon→BentoML, Metaflow→ZenML, Dataiku→DataRobot, SAS Viya→SAP.**
  These were written into the mapping and then removed — they are competing
  vendors, and rolling them together is a false positive. Real signals were found
  for all four instead.
- **`xhr` patterns for the 9 endpoint security consoles.** `falcon.crowdstrike.com`
  and `admin.zscaler.net` resolve, so patterns would have validated cleanly. But
  no company's public site calls its own EDR console, so they would never fire
  while the report claimed "detected".
- **Vendor names in page text.** `html: "Apache Airflow"` matches any blog post
  about Airflow. Every self-hosted UI pattern is anchored to a `<title>` element
  or a unique id/class; `test/dnb-technologies.test.js` asserts that prose naming
  nine of these tools detects none of them.

## Known gaps

- **The direct Samsara sign-in CLI run timed out.** The accepted Samsara marker
  still has end-to-end coverage on a real customer page, and the rejected
  Assistant marker was confirmed through an independent live browser asset
  inspection.
- **The text-signal layer is unproven on real pages.** It is unit-tested against
  synthetic postings and verified not to fire on press releases or comparison
  pages, but has not been run over a corpus of real careers pages to measure
  precision and recall.
- **19 `W_REGEX_KEY` warnings are unresolved.** Fixing them means changing keyed
  channels to match keys as regexes, which alters upstream semantics for all
  ~8,400 entries and risks false positives. Reported rather than changed.
