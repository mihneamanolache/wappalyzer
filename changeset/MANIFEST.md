## The original brief, and what it turned into

The ask was: add the technologies from the D&B spreadsheet, revamp the project,
add tests, and make the catalog "100% coherent with what gets extracted".
Auditing coherence first turned out to matter most, because the catalog was not
coherent and the update script would have made it worse.

### 1. The engine crashed on bad catalog data

`resolve()` threw on a dangling `implies`/`excludes` reference, aborting an entire
scan. Confirmed live: detecting `Juniper` or `Amazon Augmented AI` threw. Defects
are now collected on `Wappalyzer.errors` and surfaced by the validator, so one bad
entry cannot take down a run.

Also fixed in `wappalyzer.js`:

- `setTechnologies()` was not idempotent — calling it twice corrupted
  `requires`/`categoryRequires`.
- An unknown category id crashed the priority sort. Categories are now resolved
  once per detection, so an unknown id is reported once and dropped.
- `analyzeManyToMany()` had no guard for a non-object channel or a missing regex.
- `xhr` patterns must now match a whole DNS-label suffix, so `api\.vendor\.com` no
  longer matches `api.vendor.com.attacker.invalid`, nor `tome\.app` match
  `nottome.app`.
- `saas` and `oss` were curated in the data and silently dropped by the engine.
- `analyzeJs`/`analyzeDom` moved out of `driver.js` so they are testable without
  puppeteer, and the JS collector no longer aborts a page when a global is
  inaccessible.

### 2. The update script destroyed local work

`merge-update.js` replaced any technology that also existed upstream, silently
discarding locally-authored fingerprints — `Salesforce Service Cloud` and
`Microsoft Application Insights` each carry local cookie/dom/meta/xhr patterns and
far more specific `scriptSrc` lists than upstream ships.

**This was fixed before the update was run**, so nothing was lost. The merge is now
additive at field level (`scripts/lib/merge.js`); `test/merge.test.js` guards the
regression. `preferLocalShape()` also keeps the local representation when a merge
adds nothing, without which the first clean run rewrote 5,083 entries purely to
collapse `["a"]` into `"a"`.

### 3. ~180 patterns could never fire

Found by the new validator, fixed by the new normalizer:

| Defect | Count | Effect |
| --- | --- | --- |
| `script` instead of `scriptSrc` | 52 | Field not read; pattern dead |
| Keyed channel written as string/array | 16 | `analyzeManyToMany` keys on indices |
| Flat channel written as an object | 12 | `analyzeOneToOne` bails |
| Invalid `dom` rules (`content`, `version`, `exists: true`) | 29 | Collector never reports them |
| Malformed `probe` schemas | 10 | Driver would request `/0`, `/1`, … |
| Nested `js` objects | 4 | Collector does not walk into them |
| `dns` keys the driver never resolves | 3 | Channel never receives values |
| Duplicate names across letter files | 85 | Last load silently won |
| Misfiled into the wrong letter file | 590 | Churn on every merge |
| Invalid/missing category ids | 4 | Undefined category |

### 4. Coverage against the request list

47% → **96% catalog-matchable**, 100% mapped. `Catalog-matchable` means a detection
path exists and passes synthetic tests; it is **not** empirical live-scan coverage.
Two reframings did most of it:

- **"Back-end" tools ship web UIs.** Airflow, Superset, MLflow, Argo CD, Metabase,
  Prometheus, Prefect, Spark, Flink, Kiali, Ray, Kubeflow, Rancher, Kedro-Viz,
  AutoGPT and the Kubernetes/OpenShift consoles are routinely exposed on a
  subdomain. Patterns were read from each project's shipped index template.
- **A model's output is evidence of the model.** An image from
  `cdn.midjourney.com` was made with Midjourney. Generated-media CDNs plus hosted
  provider APIs cover the image, video, music and language models.

### 5. The evidence is reproducible and measured

**The DNS sweep.** Corpus committed (`data/dns-sweep-domains.txt`, 536 domains);
`scripts/dns-sweep.js` reads tokens **from the catalog**, so it measures what
ships. Latest run: 513 returned TXT records, 23 returned none, 0 failed to
resolve; **94 of 96 markers observed**. Results carry a timestamp, full SHA-256 of
the corpus and marker set, resolver details, and a per-domain resolution outcome so
a timeout is never counted as "no records". `npm run sweep:check` re-hashes both
inputs and fails when stale.

Stated precisely: **all 55 enriched technologies have at least one observed
retained marker; five original pattern strings were superseded** during redundancy
removal (Detectify, Dropbox, Segment, Mixpanel, DocuSign). 48 are observed by their
exact string. Labels are derived from the retained results at load time, not
hard-coded, and a superseded marker only inherits evidence when both patterns are
literals, containment holds, and the substitution is declared in
`EXPECTED_SUPERSESSIONS`.

**The xhr channel.** 126 of the 387 catalog-matchable products rest on `xhr` alone.
**1 of 85 xhr-only markers appeared in a 29-page corpus under the current
request-aborting driver**, while 47 xhr hostnames were collected — all marketing
and telemetry, no vendor API hosts, not even on those vendors' own sites. That is a
**yield, not an observation rate**: nothing maps each marker to a page where its
vendor is in use, the driver aborts non-document/script requests and suppresses
follow-on calls, and only 8 of 29 pages returned a clean 200. The entries were
kept; the report frames 96% as an upper bound and the yield as a lower bound.

## What was deliberately not done

Each of these would have raised a headline number and was rejected:

- **`google-site-verification`** appeared on 445 of 518 domains, the fattest token
  in the sweep. Search Console sets it too, so it says nothing about Google
  Workspace. The Workspace-specific recovery record is used instead.
- **Mapping Seldon→BentoML, Metaflow→ZenML, Dataiku→DataRobot, SAS Viya→SAP.**
  Written into the mapping, then removed — they are competing vendors. Real signals
  were found for all four instead.
- **`xhr` patterns for the 9 endpoint security consoles.** `falcon.crowdstrike.com`
  and `admin.zscaler.net` resolve, so patterns would have validated cleanly, but no
  company's public site calls its own EDR console.
- **Vendor names in page text.** `html: "Apache Airflow"` matches any blog post
  about Airflow. Every self-hosted UI pattern is anchored to a `<title>` element or
  a unique id/class, and a test asserts prose naming nine of these tools detects
  none of them.

## Known gaps

- **The D&B reply and the ETA have not been written.** This is the outstanding
  business deliverable. Both flagged priorities (Samsara, Verizon Connect) are
  built and live-verified, so the ETA is effectively "done", but nobody has told
  D&B that.
- **Empirical validation is thin: 4 live-observed targets out of 262 mapped
  technologies.** Everything else is hostname-verified plus synthetically tested.
- **The text-signal layer is unproven on real pages.** Unit-tested against
  synthetic postings and verified not to fire on press releases or comparison
  pages, but never run over a corpus of real careers pages, so its precision and
  recall are unmeasured.
- **19 `W_REGEX_KEY` warnings are unresolved.** Fixing them means matching keyed
  channels as regexes, which changes upstream semantics for ~8,400 entries and
  risks false positives.
